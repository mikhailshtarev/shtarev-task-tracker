## План работ по продукту, разбитый на фичи

Создать документ **`docs/product/work-plan.md`** — план работ для PM/команды, разбитый на 19 фич в порядке реализации, где каждая фича зависит только от предыдущих. Фичи 1–17 составляют MVP, фича 18 помечена как post-MVP, фича 19 — соответствие требованиям к персональным данным. В конце документа — раздел «Следующие шаги»: для каждой фичи перед разработкой составляется техническая спецификация + план работ (как это уже сделано для авторизации в `docs/technical/auth/`).

Содержимое документа:

### Ф1. Инфраструктура и каркас платформы
Docker Compose окружение с PostgreSQL, Redis, Kafka, MinIO; скелет API Gateway (маршрутизация, CORS, rate limiting) и CI-пайплайн (сборка, тесты). Подключение наблюдаемости по NFR 16–17: OpenTelemetry, Jaeger, correlation ID, метрики и алерты. Критерий готовности — новый микросервис добавляется в окружение без ручной настройки.

### Ф2. Аутентификация и авторизация
Сервис auth и фронтенд-страницы по уже готовым планам (`docs/technical/auth/`): регистрация с подтверждением email, вход по паролю и через Google OAuth, JWT с single-use refresh, смена и сброс пароля, восстановление сессии. Публикация JWKS для валидации токенов остальными сервисами. Спецификация и детальные планы существуют — фича стартует первым делом после Ф1.

### Ф3. Персональные настройки и профиль
Единица оценки (часы/помидоры с длительностью помидора), базовые награды игрового режима (e, z) и переключатель игрового режима. Настройки привязаны к пользователю; все расчёты хранятся точно в часах, пересчёт — только для отображения (NFR 4.6). От этой фичи зависят задачи, привычки и игровой режим.

### Ф4. Ветки
CRUD направлений жизни («Работа», «Спорт» и т. д.) с валидацией названия 2–100 символов. Архивирование ветки уносит с собой все планы и задачи. Первый контур данных + REST + экран списка.

### Ф5. Планы работ
CRUD планов внутри ветки: создание, переименование, архивирование вместе с задачами, отображение задач плана. Валидация названия 2–150 символов.

### Ф6. Задачи
Полная модель задачи из БТ 4.3: заголовок, описание, дата, приоритет Эйзенхауэра, статусы канбана, плановая оценка и фактическое время (в единице из настроек Ф3), сложность, триггер ожидания и дата возврата. Быстрые действия «Сделать сегодня/завтра», обязательное фактическое время при завершении, все валидации из БТ 5.2.1. Самая объёмная фича продуктового ядра.

### Ф7. Входящие мысли
Раздел «Входящие» для быстрых записей: создание, редактирование, архивирование, список неразобранных. Преобразование записи в задачу с выбором ветки, плана, приоритета и даты; исходная запись архивируется после преобразования.

### Ф8. Канбан-доска
Единая доска по всем веткам и планам: режимы «Сегодня» и «Общий», четыре колонки, перенос задачи меняет статус, дата «сегодня» включает задачу в режим «Сегодня». Фильтры и сортировки по NFR 8, просмотр завершённых за месяц и более ранних отдельным действием. Карточка показывает заголовок, приоритет, ветку и план.

### Ф9. Архив и история изменений
Единый раздел архива и правила восстановления из БТ 5.1: восстановление ветки (всё или только ветка), плана, задачи с авто-разархивированием родителей, частичные восстановления. Техническая история изменений всех сущностей. Операции в транзакциях с откатом (NFR 4.3).

### Ф10. Заметки и папки
Иерархические папки до 7 уровней вложенности, CRUD заметок, перемещение между папками, поиск по заголовку и содержимому. Области-теги (1–5 на заметку) и фильтрация по ним. Валидации из БТ 5.2.3.

### Ф11. Дневник и медиафайлы
CRUD записей дневника с датой и хронологическим просмотром. Загрузка фото/видео в S3: форматы и лимиты NFR 6.2, конвертация HEIC, авто-сжатие при превышении, дедупликация SHA-256. Лимит 3 ГБ на пользователя, уведомления при 80 %, блокировка загрузок при 100 %.

### Ф12. Привычки и операционный день
CRUD привычек двух типов («отметки» и «количество») с дневной целью, дневной прогресс, история выполнения. Операционный день 04:00 МСК: закрытие и сохранение прогресса, новый день, изменение цели в течение дня. Окно корректировки вчерашнего прогресса (БТ раздел 9).

### Ф13. Игровой режим: база
Профиль персонажа, уровни 1–100 со званиями и прогрессией «+10 % к следующему уровню», опыт за задачи по формуле x×k×e, игровая валюта и личный бюджет по x×k×z, списания бюджета с подтверждением свыше 100. Включение/выключение в настройках; на этом этапе доступ как пробный период 14 дней от первой задачи — без платежей.

### Ф14. Навыки и ИИ-распределение опыта
Пять базовых навыков; при завершении задачи данные уходят в Kafka-топик `ai.task.skill.distribution`, ИИ возвращает навыки и доли опыта. Fallback: некорректный ответ — равные доли, 5 неудач — DLT и расчёт по умолчанию. Уведомление пользователю о некорректной обработке с возможностью повторного анализа.

### Ф15. Подписки и уровни доступа
Тарифы Старт/Прогресс/Эволюция, помесячная и годовая оплата, пробный период игрового режима и его блокировка по окончании, переходы между тарифами с доплатой. Гейтинг всех платных функций, включая покупку дополнительного хранилища (NFR 6.3.1). Требует отдельного решения по платёжному провайдеру.

### Ф16. ИИ-анализ привычек
В 04:00 МСК результаты операционного дня уходят в `ai.habits.daily.analysis`; ИИ начисляет опыт, валюту и опыт навыков за привычки. До 5 повторов при ошибке, затем расчёт по умолчанию; обработка асинхронная и не блокирует новый операционный день. Доступна только при активном игровом режиме по тарифу.

### Ф17. Достижения (каркас)
Сущности достижений: название, условие, награда, статус разблокировки, отображение в игровом профиле. Перечень и условия — отдельный документ; в этой фиче реализуется только каркас хранения без активных достижений (NFR 13.1).

### Ф18. Push-уведомления (post-MVP)
Web Push/FCM по NFR 18: подписка браузера, уведомления о дате возврата, завершении задачи, ИИ-анализе и подписке, настройки по типам, тихие часы 22:00–08:00. Спецификация готова, но явно помечена вне MVP — реализуется после стабилизации ядра.

### Ф19. Данные пользователя: экспорт и удаление
Экспорт всех данных пользователя по запросу и полное удаление с анонимизацией (NFR 5.2). Аудит обеих операций. Небольшая фича, закрывает требования к персональным данным.
