# F-5.1. Дерево проектов, планов и задач — системное описание

## 1. Архитектура

Фича добавляет единый read-model и endpoint для левой навигации поверх сервисов `tasks`. Gateway сохраняет проверку access JWT и подписанный внутренний контекст пользователя. Клиент получает каждый уровень дерева через единый endpoint с дозагрузкой по выбранному родителю, а не отдельный контракт для каждого типа сущности; операции создания используют существующие контракты F-4/F-6 с контекстом родителя.

```text
Frontend ── GET /api/v1/navigation/tree ──▶ Gateway ──▶ Tasks service
       │                                      │             ├── branches (parent_id)
       │                                      │             ├── work_plans
       │                                      │             └── tasks
       └── POST create branch/task ───────────┘
```

Планы работ входят в узлы дерева под веткой. Задачи с `work_plan_id` отображаются под планом, остальные — непосредственно под веткой. Поля и операции плана остаются определёнными F-5.

## 2. Модель данных

### 2.1. Ветки

Миграция F-5.1 добавляет в `branches`:

| Поле | Тип | Ограничения |
| --- | --- | --- |
| `parent_id` | UUID | `NULL` для корня; внешний ключ на `branches.id`, `ON DELETE RESTRICT` |
| `depth` | SMALLINT | 1–7; вычисляется сервером и проверяется при записи |

Индекс `(user_id, parent_id, created_at DESC, id DESC) WHERE archived_at IS NULL` обслуживает выдачу соседей. Сервер проверяет, что родитель принадлежит тому же пользователю, активен, не является самой веткой или её потомком, а новый `depth` не превышает 7. Физическое удаление запрещено.

### 2.2. Узлы дерева

Read-model узла содержит `id`, `type` (`branch`, `work_plan` или `task`), `parentId` (для плана — `branchId`, для задачи — `workPlanId` либо `branchId`), `name`, `depth`, `hasChildren`, `archivedAt` (только для внутренних проверок) и краткие поля задачи из контракта F-6. Архивированные узлы не выдаются.

## 3. API-контракты

### 3.1. `GET /api/v1/navigation/tree`

Возвращает только непосредственных активных детей указанного узла текущего пользователя. При первом открытии `parentId` и `parentType` отсутствуют — сервис возвращает только корневые проекты. Для раскрытия проекта клиент передаёт `parentType=branch&parentId=...`; для раскрытия плана — `parentType=work_plan&parentId=...`. Запрос не принимает `userId`. Для большого числа соседей используется `limit` 1–500 и непрозрачный `cursor`; при наличии следующей страницы возвращается `nextCursor`. Gateway отдаёт публичный `401` для недействительного access JWT, а `tasks` принимает только подписанный контекст F-4.

Пример:

```json
{
  "items": [
    {"id":"…","type":"branch","parentId":null,"name":"Работа","depth":1,"hasChildren":true}
  ],
  "nextCursor": null
}
```

Сервис не выполняет N+1: при раскрытии одного узла ветки, планы и задачи его непосредственного уровня выбираются наборными запросами с ограничением владельца и статуса. Клиент догружает только выбранный уровень, сохраняет его в кэше раскрытых узлов и не запрашивает повторно без явного обновления.

### 3.2. Создание ветки

Существующий `POST /api/v1/branches` расширяется необязательным полем `parentId`:

```json
{"name":"Проект X","parentId":"8f20d971-bdd8-4d2b-82ea-5fd4e126532f"}
```

Отсутствующий `parentId` создаёт корневую ветку. Чужой, архивированный, циклический или слишком глубокий родитель даёт `400 VALIDATION_ERROR` либо `404 NOT_FOUND` по правилам F-4. Ответ сохраняет формат `201 Created` и добавляет `parentId`, `depth`.

### 3.3. Создание задачи

F-5.1 вызывает публичный контракт создания задачи F-6, передавая `branchId` выбранного узла. Клиент не передаёт произвольный `userId`; сервер проверяет владельца ветки и принадлежность указанного плана.

### 3.4. Архивирование

Существующие endpoints `POST /api/v1/branches/{branchId}/archive` и `POST /api/v1/tasks/{taskId}/archive` не меняются. UI вызывает их только со страницы сущности после подтверждения. Архивирование ветки выполняется транзакционно для всей дочерней иерархии, планов и задач, включая уже архивированные дочерние сущности; архивирование задачи затрагивает только задачу. После успеха UI возвращает пользователя к непосредственному родителю, а для корневого проекта — в раздел «Проекты».

## 4. Frontend-состояние и доступность

- `NavigationTree` хранит нормализованную коллекцию узлов по `id`, набор раскрытых папок и состояние догрузки каждого родительского уровня.
- `AuthenticatedLayout` хранит ширину левой колонки в CSS custom property, ограничивает её диапазоном 180–480 px и сохраняет значение в `localStorage`. Разделитель реализован доступной клавиатурной кнопкой: стрелки изменяют ширину, `Home`/`End` устанавливают границы.
- После создания дочернего узла раскрывается родитель, а после архивации узел удаляется из активной коллекции без полной перезагрузки.
- Если Gateway временно не содержит маршрут `/navigation/tree` или возвращает устаревший `400/404`, клиент использует совместимый `GET /branches` для отображения существующих проектов текущего пользователя; после восстановления маршрута снова используется иерархический read-model.
- Поиск и фильтры не меняют серверную авторизацию; при смене пользователя состояние дерева очищается.
- Кнопка «+» — отдельная доступная кнопка с `aria-label`, меню закрывается по `Escape` и не отправляет запрос до выбора действия.
- Архивная кнопка на странице сущности расположена в правом верхнем углу, имеет подтверждение и блокируется на время запроса.

## 5. Надёжность и безопасность

- Все запросы к дереву и операции записи требуют access JWT и проверку владельца на сервере.
- Клиентские `parentId` и `branchId` считаются недоверенными; сервер повторно проверяет активность, владельца и глубину.
- Архивирование ветки и её потомков выполняется в одной транзакции с аудитом; частичный результат запрещён.
- Ошибки не раскрывают существование чужих веток или задач; пользователь получает понятный текст без SQL, stack trace и внутренних заголовков.

## 6. Влияние на фичи

| Фича | Изменение |
| --- | --- |
| F-4 | Добавляет `parentId`/`depth` и сохраняет обратную совместимость плоского списка |
| F-5 | Планы входят в read-model дерева под родительской веткой и остаются доступны на странице ветки |
| F-6 | Предоставляет создание и архивирование задач, используемые меню «+» |
| F-9 | Добавляет просмотр и восстановление архивной иерархии |
