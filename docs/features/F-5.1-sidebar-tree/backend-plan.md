# План работ: F-5.1 Дерево проектов, планов и задач — Backend

## 0. Контекст для агента

Перед началом прочитай `AGENTS.md`, [business-description.md](business-description.md), [system-description.md](system-description.md), контракты F-4/F-5/F-6 и общий контракт Gateway. Работай только в backend-модулях, необходимых для дерева и расширения контрактов веток. Не редактируй применённые миграции: добавь новую миграцию.

## 1. Схема и доменная модель

- [ ] Добавить миграцию с `branches.parent_id`, `branches.depth`, внешним ключом и индексом активных соседей.
- [ ] Расширить доменную модель и DTO полями `parentId` и `depth`.
- [ ] Реализовать серверную проверку владельца, активного родителя, циклов и предельной глубины 7.

**Готовность:** миграция применяется на чистой и существующей базе, запрещает некорректные связи и не меняет публичное поведение корневых веток.

## 2. API веток и дерево

- [ ] Расширить `POST /api/v1/branches` необязательным `parentId` с валидацией и обратной совместимостью.
- [ ] Добавить `GET /api/v1/navigation/tree` с keyset-пагинацией, лимитом 1–500 и наборной загрузкой веток/планов/задач без N+1.
- [ ] Сохранить единый формат ошибок и доверенный контекст Gateway → tasks.

**Готовность:** чужие данные не выдаются, курсор валидируется, дерево собирается за фиксированное число запросов к БД.

## 3. Архивирование и транзакции

- [ ] Расширить каскад архивирования ветки на всех потомков, планы и задачи, сохранив единый момент и аудит.
- [ ] Проверить блокировки и откат при сбое; не создавать повторные события для уже архивированных сущностей.

**Готовность:** операция атомарна и идемпотентна по контракту F-4/F-5.

## 4. Интеграция с задачами

- [ ] Согласовать с F-6 создание задачи через выбранный `branchId` и запрет чужого/архивированного родителя.
- [ ] Добавить endpoint- и security-тесты для дерева, `parentId`, глубины, циклов и каскада.

**Готовность:** API позволяет безопасно создать задачу из узла дерева без передачи `userId` клиентом.

## 5. Финальная проверка

- [ ] Выполнить unit- и integration-тесты затронутых backend-модулей.
- [ ] Сверить endpoints с системным описанием и OpenAPI F-4/F-6.
- [ ] Проверить миграцию, аудит, отсутствие N+1 и регрессию плоского списка веток.

## 6. Тест-кейсы

| # | Сценарий | Ожидание |
| --- | --- | --- |
| BE-01 | Создание корневой ветки без `parentId` | `201`, `depth=1` |
| BE-02 | Создание дочерней ветки | `201`, корректные `parentId` и `depth` |
| BE-03 | Восьмой уровень | `400 VALIDATION_ERROR`, запись не создана |
| BE-04 | Чужой или архивированный родитель | Ошибка без раскрытия данных |
| BE-05 | Циклическая связь | `400`, состояние БД не изменилось |
| BE-06 | Выдача дерева двух пользователей | Каждый получает только собственные активные узлы |
| BE-07 | Догрузка страницы дерева | Нет дублей, курсор привязан к запросу |
| BE-08 | Каскадное архивирование ветки | Потомки, планы и задачи архивированы одной транзакцией |
| BE-09 | Сбой каскада | Полный откат сущностей и аудита |
| BE-10 | Создание задачи в ветке | Задача принадлежит выбранной ветке; `userId` из тела игнорируется/отклоняется |
