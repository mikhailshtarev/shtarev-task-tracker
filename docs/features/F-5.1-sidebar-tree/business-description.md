# F-5.1. Дерево проектов, планов и задач — бизнес-описание

## 1. Назначение

F-5.1 перестраивает авторизованную навигацию в единое рабочее дерево по принципу Notion. Пользователь управляет активными ветками и задачами непосредственно в левой панели, а не через разрозненные списки.

Фича использует ветки F-4, планы F-5 и задачи F-6. В левом дереве отображается полный список этих сущностей.

Все пользовательские тексты на фронтенде используют термин «проект»: «Проекты», «Новый проект», «Архивировать проект». Внутри API, базы данных и технической документации сохраняется доменное имя `branch`/«ветка».

## 2. Пользовательская ценность

Пользователь видит структуру своих направлений и текущих задач в одном месте, быстро раскрывает нужную ветку и создаёт дочернюю ветку или задачу без перехода в отдельный список.

## 3. Пользовательский интерфейс

### 3.1. Расположение навигации

- Профиль и настройки находятся в правом верхнем углу шапки рядом с текущим пользователем и выходом.
- Левая колонка имеет изменяемую ширину: пользователь может перетащить разделитель между навигацией и содержимым, чтобы подобрать удобный размер.
- В левой колонке статичные разделы идут сверху вниз; «Проекты» является последним статичным пунктом.
- Под пунктом «Проекты» располагается дерево активных проектов, планов работ и задач.

### 3.2. Дерево

- Внизу дерева всегда доступна плашка «Новый проект» для создания корневого проекта.
- Проект отображается как папка с названием, состоянием раскрытия и кнопкой «+» справа.
- Нажатие «+» открывает меню с действиями «Новый проект» и «Новая задача».
- «Новый проект» создаёт дочерний проект выбранного проекта; «Новая задача» создаёт задачу непосредственно в выбранном проекте.
- План отображается дочерним элементом проекта и ведёт на страницу плана. Задача, связанная с планом, отображается под планом; задача без плана — дочерним элементом проекта.
- При открытии раздела загружается только корневой уровень проектов. Дочерние проекты, планы и задачи загружаются по нажатию стрелки раскрытия у соответствующего проекта или плана; повторное раскрытие не делает новый запрос без обновления данных.
- Вложенность проектов ограничена 7 уровнями. Архивированные узлы не отображаются в активном дереве.

### 3.3. Архивирование

- В дереве нет destructive-действия архивирования.
- После открытия проекта или задачи в правом верхнем углу страницы отображается кнопка «Архивировать проект» или «Архивировать задачу».
- Перед операцией показывается подтверждение с понятным описанием последствий.
- Архивирование проекта архивирует всю его иерархию, планы и задачи по общим правилам продукта, включая уже архивированные дочерние сущности. Архивирование задачи не меняет соседние сущности.

## 4. Бизнес-правила

| Правило | Требование |
| --- | --- |
| Владелец | Пользователь видит и изменяет только собственные ветки и задачи |
| Родитель проекта | Родитель необязателен для корневого проекта; при создании дочернего проекта указывается текущий проект |
| Глубина | Максимум 7 уровней; сервер отклоняет восьмой уровень и циклические связи |
| Задача | Всегда принадлежит одной ветке; план работ необязателен и должен принадлежать той же ветке |
| Создание | Корневые проекты создаются плашкой «Новый проект», дочерние проекты и задачи — через «+» |
| Архив | Архивирование проекта или задачи доступно только на странице открытой сущности и требует подтверждения |
| Согласованность | После создания, переименования или архивации дерево обновляется без дубликатов и раскрывает затронутую ветку |

## 5. Пользовательские сценарии

### Сценарий 1. Создать корневой проект

1. Пользователь нажимает плашку «Новый проект» внизу дерева.
2. Вводит название и подтверждает форму.
3. Новый проект появляется последним корневым узлом и открывается.

### Сценарий 2. Создать дочерний проект

1. Пользователь раскрывает проект «Работа».
2. Нажимает «+» справа от названия.
3. Выбирает «Новый проект», вводит «Проект X» и подтверждает.
4. «Проект X» появляется внутри «Работа» на следующем уровне.

### Сценарий 3. Создать задачу из дерева

1. Пользователь нажимает «+» у проекта «Проект X».
2. Выбирает «Новая задача».
3. Заполняет обязательные поля задачи и подтверждает.
4. Задача появляется дочерним узлом проекта и доступна по ссылке.

### Сценарий 4. Архивировать сущность

1. Пользователь открывает проект или задачу.
2. Нажимает «Архивировать проект» или «Архивировать задачу» в правом верхнем углу.
3. Подтверждает действие.
4. Система сохраняет данные, убирает сущность из активного дерева и возвращает пользователя к непосредственному родителю: для корневого проекта — в раздел «Проекты», для задачи под планом — на страницу плана.

## 6. Критерии приёмки

1. «Проекты» — последний статичный пункт левой навигации, профиль и настройки находятся справа сверху.
2. Левая колонка изменяет ширину перетаскиванием разделителя и сохраняет выбранный размер при следующем открытии приложения.
3. В левом дереве отображаются все доступные активные проекты, планы и задачи текущего пользователя.
4. Плашка «Новый проект» создаёт корневой проект.
5. Кнопка «+» у проекта предлагает ровно два действия: «Новый проект» и «Новая задача».
6. Дочерняя ветка и задача создаются в выбранном родительском контексте без ручного ввода идентификаторов.
7. Ветка не может быть создана глубже 7 уровней или с циклическим родителем.
8. В дереве отображаются проекты, планы и задачи; задачи с планом вложены под соответствующим планом. При первом открытии загружается только корневой уровень, остальные узлы — по стрелке раскрытия проекта или плана.
9. Архивирование проекта или задачи выполняется только на странице сущности в правом верхнем углу, требует подтверждения и возвращает к родителю.
10. Сценарии создания и изменения ширины доступны с клавиатуры (`Tab`, `Enter`, `Escape`, стрелки), а повторное нажатие во время запроса не создаёт дубликат.

## 7. Зафиксированные решения

- Максимальная глубина проектов — 7 уровней.
- Дерево содержит проекты, планы и задачи. Планы отображаются под проектом, а связанные задачи — под планом.
- При входе загружается только корневой уровень; дочерние элементы загружаются по стрелке раскрытия проекта или плана.
- Все пользовательские подписи используют «Проект», а технические идентификаторы сохраняют `branch`.

## 8. Вне рамок F-5.1

- просмотр и восстановление архива — F-9;
- изменение статуса и канбан задачи — F-6/F-8;
- перемещение существующей ветки между родителями;
- совместный доступ и роли.
