# План работ: F-5.1 Дерево проектов, планов и задач — Frontend

## 0. Контекст для агента

Перед началом прочитай `AGENTS.md`, [business-description.md](business-description.md), [system-description.md](system-description.md), дизайн-систему и контракты F-4/F-5/F-6. Работай в `frontend/src`; все тексты на русском и вынесены в модуль строк. Отображай планы работ отдельными узлами под ветками.

## 1. Навигационный layout

- [ ] Оставить профиль и настройки в правом верхнем углу шапки.
- [ ] Сделать «Проекты» последним статичным пунктом левой навигации (технический идентификатор раздела сохраняется как branches).
- [ ] Разместить под ним `NavigationTree` и корневую плашку «Новый проект».

**Готовность:** порядок элементов совпадает с дизайн-системой на desktop и адаптивных брейкпоинтах.

## 2. Дерево

- [ ] Добавить типы узлов проекта/плана/задачи, нормализованное состояние и загрузку только корневого уровня через `GET /api/v1/navigation/tree`.
- [ ] Реализовать раскрытие/сворачивание проектов и планов, догрузку непосредственных детей по стрелке и индикацию папки; скрывать архивированные узлы.
- [ ] Сделать левую колонку изменяемой по ширине (мышь/клавиатура), сохранить значение локально и корректно отключать разделитель на мобильном экране.
- [ ] Добавить совместимый fallback на `GET /api/v1/branches`, чтобы уже существующие корневые проекты не исчезали во время обновления Gateway.
- [ ] Добавить кнопку «+» с меню «Новый проект»/«Новая задача» у каждого проекта.
- [ ] Восстанавливать раскрытый родительский контекст после создания, догружать только выбранный уровень и не допускать дублирования узлов.

**Готовность:** дерево отображает только данные текущего пользователя и работает при пустом состоянии и пагинации.

## 3. Создание сущностей

- [ ] Подключить форму корневого/дочернего проекта с передачей `parentId` и клиентской проверкой глубины.
- [ ] Подключить форму задачи F-6 с автоматически выбранным проектом; не показывать поле `userId`.
- [ ] Обработать ошибки валидации, конфликт устаревшего дерева и сетевой повтор без технических деталей.

**Готовность:** корневой проект создаётся плашкой, дочерний проект и задача — через «+» выбранного родителя.

## 4. Страницы и архивирование

- [ ] На странице проекта и задачи разместить кнопки «Архивировать проект»/«Архивировать задачу» в правом верхнем углу.
- [ ] Сделать единый подтверждающий диалог с блокировкой повторного запроса и возвратом фокуса.
- [ ] После успешной операции удалить узел из дерева и вернуть пользователя к родительскому контексту.

**Готовность:** архивирование недоступно непосредственно в дереве и не оставляет устаревший узел.

## 5. Доступность и адаптивность

- [ ] Поддержать `Tab`, `Enter`, `Escape`, ARIA-метки для раскрытия, «+» и меню.
- [ ] На мобильном экране преобразовать колонку в горизонтальную панель согласно дизайн-системе, сохранив доступ к дереву.
- [ ] Проверить контраст, фокус и понятные русские тексты ошибок.

## 6. Финальная проверка

- [ ] Выполнить `npm test` и `npm run build`.
- [ ] Проверить сценарии пустого дерева, вложенности 7 уровней, пагинации, создания и архивации через реальный Gateway.
- [ ] Убедиться, что планы работ отображаются отдельными узлами под веткой, а задачи с планом — под соответствующим планом.
