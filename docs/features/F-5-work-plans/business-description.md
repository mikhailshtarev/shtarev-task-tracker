# F-5. Планы работ — бизнес-описание

## 1. Назначение

План работ объединяет связанные задачи внутри одной ветки. Он помогает пользователю разделить крупное направление на понятные наборы действий: например, в ветке «Здоровье» создать планы «Чекап» и «Тренировки».

Фича зависит от F-4 «Ветки» и создаёт необязательную группировку для задач F-6. Источники: [общие бизнес-требования](../../product/business-requirements.md), разделы 3, 4.1, 4.2, 5.1 и 5.2.2; [нефункциональные требования](../../product/non-functional-requirements.md), разделы 3–5 и 15; [план работ продукта](../../product/work-plan.md), F-5.

В F-5.1 планы остаются частью родительской ветки и дополнительно отображаются отдельными узлами полного левого дерева. Управление планом (переименование и архивирование) выполняется на его странице или странице ветки.

## 2. Пользовательская ценность

Пользователь превращает общее жизненное направление в несколько самостоятельных планов. Благодаря этому задачи не смешиваются: например, работа по новому проекту отделяется от изучения нового навыка, хотя оба плана находятся в ветке «Работа».

## 3. Бизнес-функциональность

### 3.1. Просмотр планов ветки

На странице активной ветки пользователь видит её активные планы работ. В карточке плана отображается как минимум название. Если планов нет, интерфейс показывает понятное пустое состояние и действие «Создать план».

Пользователь может искать планы текущей ветки по части названия без учёта регистра. При большом числе планов результаты загружаются страницами без повторов.

### 3.2. Создание плана

Пользователь создаёт план внутри выбранной активной ветки, указав название. Новый план может быть пустым: добавлять задачу для его создания не требуется. Он сразу появляется в списке ветки и становится доступен для группировки задач после реализации F-6. Задачу можно будет создать и без плана.

### 3.3. Переименование

Пользователь может изменить название активного плана. Изменение названия не меняет принадлежность плана к ветке и не влияет на будущие задачи внутри него.

### 3.4. Открытие плана

Пользователь может открыть активный план и увидеть его название и родительскую ветку. После реализации F-6 на этой странице отображаются задачи плана.

### 3.5. Архивирование

Пользователь архивирует план вместо физического удаления. Архивированный план исчезает из обычного списка ветки, но все его данные сохраняются.

После реализации F-6 архивирование плана будет переводить в архив все его задачи. Если пользователь архивирует ветку, F-5 обеспечивает архивирование всех вложенных планов вместе с веткой. Восстановление планов и веток выполняется в F-9 «Архив и история».

## 4. Бизнес-правила

| Правило | Требование |
| --- | --- |
| Принадлежность | План принадлежит ровно одной ветке |
| Наполнение | Пустой план разрешён; число задач в плане может быть любым, а привязка задачи к плану необязательна |
| Активная ветка | Создать или открыть активный план можно только в активной ветке текущего пользователя |
| Название | От 2 до 150 символов после удаления начальных и конечных пробелов |
| Уникальность | Повторяющиеся названия планов внутри ветки допустимы |
| Удаление | Физическое удаление не применяется; в интерфейсе используется действие «Архивировать» |
| Архив плана | Архивированный план не входит в обычный список и недоступен для создания новых задач |
| Архив ветки | При архивировании ветки архивируются все её планы; операция выполняется целиком либо не выполняется вовсе |
| Архив задач | После F-6 при архивировании плана архивируются все его задачи |
| История | Создание, переименование и архивирование подлежат техническому аудиту, в том числе архивирование активного плана вместе с веткой; просмотр истории реализуется в F-9 |

## 5. Пользовательские сценарии

### Сценарий 1. Добавить план в ветку

1. Пользователь открывает ветку «Здоровье».
2. Нажимает «Создать план».
3. Вводит «Тренировки» и подтверждает действие.
4. Система создаёт план и отображает его внутри ветки.

### Сценарий 2. Переименовать план

1. Пользователь открывает действия плана «Тренирвоки».
2. Выбирает «Переименовать» и вводит «Тренировки».
3. Система сохраняет новое название и подтверждает изменение.

### Сценарий 3. Завершить работу по плану

1. Пользователь выбирает «Архивировать» для плана «Чекап».
2. Система сообщает, что план будет скрыт, а данные сохранятся.
3. После подтверждения план исчезает из активного списка ветки.
4. Пользователь сможет восстановить его через F-9.

## 6. Критерии приёмки

1. Авторизованный пользователь может создать план с названием от 2 до 150 символов внутри собственной активной ветки.
2. План сразу отображается в списке этой ветки и не отображается в других ветках.
3. Название короче 2 или длиннее 150 символов не сохраняется; пользователь видит понятную ошибку.
4. Пользователь не может читать, создавать, изменять или архивировать планы в чужой или архивированной ветке.
5. Пользователь может переименовать только собственный активный план.
6. Архивированный план отсутствует в обычном списке, остаётся в хранилище и не может быть изменён.
7. При архивировании ветки все её планы архивируются в той же транзакции.
8. Создание, переименование и архивирование плана регистрируются в техническом аудите.
9. Поиск находит только активные планы текущей ветки и не раскрывает планы другой ветки или пользователя.
10. План создаётся и отображается без задач.
11. При архивировании ветки для каждого ранее активного плана создаётся одно событие технического аудита; уже архивированные планы не получают повторное событие.

После реализации F-6 дополнительно проверяется, что задачу можно создать без плана и что при указании плана он принадлежит той же ветке. Этот критерий не блокирует приёмку F-5, поскольку задач в F-5 ещё нет.

## 7. Вне рамок F-5

- перестройка левой навигации и иерархическое дерево веток, планов и задач — F-5.1;
- создание, отображение и архивирование задач — F-6;
- общий архив, восстановление и пользовательский просмотр истории — F-9;
- перемещение плана между ветками — вне первой версии;
- совместный доступ и роли — вне первой версии.
