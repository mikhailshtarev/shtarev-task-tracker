# План работ по продукту

План разбит на фичи в порядке реализации: каждая фича — отдельный выполнимый функционал, который зависит только от уже реализованных предыдущих фич. Основа — бизнес-требования ([business-requirements.md](business-requirements.md)) и нефункциональные требования ([non-functional-requirements.md](non-functional-requirements.md)).

Фичи F-1–F-17 составляют MVP. Фича F-18 помечена как post-MVP в самих NFR. F-19 закрывает требования к персональным данным.

## F-1. Инфраструктура и каркас платформы

Docker Compose окружение с PostgreSQL, Redis, Kafka и MinIO; скелет API Gateway (маршрутизация, CORS, rate limiting) и CI-пайплайн (сборка, тесты). Подключение наблюдаемости по NFR 16–17: OpenTelemetry, Jaeger, correlation ID, метрики и алерты. Критерий готовности — новый микросервис добавляется в окружение без ручной настройки.

## F-2. Аутентификация и авторизация

Сервис auth и фронтенд-страницы по уже готовым планам (`../technical/auth/`): регистрация с подтверждением email, вход по паролю и через Google OAuth, JWT с single-use refresh, смена и сброс пароля, восстановление сессии. Публикация JWKS для валидации токенов остальными сервисами. Спецификация и детальные планы для фронта и бэка существуют — фича стартует первым делом после F-1.

## F-3. Персональные настройки и профиль

Единица оценки (часы/помидоры с длительностью помидора), базовые награды игрового режима (фиксированное `e = 5` и настраиваемое `z`) и переключатель игрового режима. Настройки привязаны к пользователю; все расчёты хранятся точно в часах, пересчёт — только для отображения (БТ 4.6). От этой фичи зависят задачи, привычки и игровой режим.

## F-4. Ветки

CRUD направлений жизни («Работа», «Спорт», «Здоровье», «Дом») с валидацией названия 2–100 символов. Архивирование ветки уносит с собой все планы и задачи. Первый контур данных + REST + экран списка.

## F-5. Планы работ

CRUD планов внутри ветки: создание, переименование, архивирование вместе с задачами, отображение задач плана. Валидация названия 2–150 символов.

## F-6. Задачи

Полная модель задачи из БТ 4.3: заголовок, описание, дата, приоритет Эйзенхауэра, статусы канбана, плановая оценка и фактическое время (в единице из настроек F-3), сложность, триггер ожидания и дата возврата. Быстрые действия «Сделать сегодня/завтра», обязательное фактическое время при завершении, все валидации из БТ 5.2.1. Самая объёмная фича продуктового ядра.

## F-7. Входящие мысли

Раздел «Входящие» для быстрых записей: создание, редактирование, архивирование, список неразобранных. Преобразование записи в задачу с выбором ветки, плана, приоритета и даты; исходная запись архивируется после преобразования.

## F-8. Канбан-доска

Единая доска по всем веткам и планам: режимы «Сегодня» и «Общий», четыре колонки, перенос задачи меняет статус, дата «сегодня» включает задачу в режим «Сегодня». Фильтры и сортировки по NFR 8, просмотр завершённых за месяц и более ранних отдельным действием. Карточка показывает заголовок, приоритет, ветку и план.

## F-9. Архив и история изменений

Единый раздел архива и правила восстановления из БТ 5.1: восстановление ветки (всё содержимое или только ветка), плана, задачи с авто-разархивированием родителей, частичные восстановления. Техническая история изменений всех сущностей (создание, редактирование, статус, дата, архивирование). Операции в транзакциях с откатом (NFR 4.3).

## F-10. Заметки и папки

Иерархические папки до 7 уровней вложенности, CRUD заметок, перемещение между папками, поиск по заголовку и содержимому. Области-теги (1–5 на заметку) и фильтрация по ним. Валидации из БТ 5.2.3.

## F-11. Дневник и медиафайлы

CRUD записей дневника с датой и хронологическим просмотром. Загрузка фото/видео в S3: форматы и лимиты NFR 6.2, конвертация HEIC, авто-сжатие при превышении, дедупликация SHA-256. Лимит 3 ГБ на пользователя, уведомление при 80 %, блокировка загрузок при 100 %.

## F-12. Привычки и операционный день

CRUD привычек двух типов («отметки» и «количество») с дневной целью, дневной прогресс, история выполнения. Операционный день 04:00 МСК: закрытие и сохранение прогресса, начало нового дня, изменение цели в течение дня. Окно корректировки вчерашнего прогресса (БТ раздел 9).

## F-13. Игровой режим: база

Профиль персонажа, уровни 1–100 со званиями и прогрессией «+10 % к следующему уровню», опыт за задачи по формуле `x × k × e` при фиксированном `e = 5`, игровая валюта и личный бюджет по `x × k × z`, списания бюджета с подтверждением свыше 100 (NFR 11). Включение/выключение в настройках; на этом этапе доступ как пробный период 14 дней от первой задачи — без платежей.

## F-14. Навыки и ИИ-распределение опыта

Пять базовых навыков; при завершении задачи данные уходят в Kafka-топик `ai.task.skill.distribution`, ИИ возвращает навыки и доли опыта. Fallback: некорректный ответ (сумма долей ≠ 100 %) — равные доли; 5 неудач — DLT и расчёт по умолчанию. Уведомление пользователю о некорректной обработке с возможностью повторного анализа.

## F-15. Подписки и уровни доступа

Тарифы Старт/Прогресс/Эволюция, помесячная и годовая оплата (БТ 4.10.1), пробный период игрового режима и его блокировка по окончании (БТ 4.10.3), переходы между тарифами с доплатой (БТ 4.10.2). Гейтинг всех платных функций, включая покупку дополнительного хранилища (NFR 6.3.1). Требует отдельного решения по платёжному провайдеру — принять до старта фичи.

## F-16. ИИ-анализ привычек

В 04:00 МСК результаты операционного дня уходят в Kafka-топик `ai.habits.daily.analysis`; ИИ начисляет опыт, валюту и опыт навыков за привычки. До 5 повторов при ошибке, затем расчёт по умолчанию (NFR 9.3); обработка асинхронная и не блокирует начало нового операционного дня. Доступна только при активном игровом режиме по тарифу.

## F-17. Достижения (каркас)

Сущности достижений: название, условие, награда, статус разблокировки, отображение в игровом профиле. Перечень и условия — отдельный документ; в этой фиче реализуется только каркас хранения без активных достижений (NFR 13.1).

## F-18. Push-уведомления (post-MVP)

Web Push/FCM по NFR 18: подписка браузера, уведомления о дате возврата к задаче, завершении задачи, ИИ-анализе и подписке, настройки по типам, тихие часы 22:00–08:00. Спецификация готова, но явно помечена вне MVP — реализуется после стабилизации ядра. Требует HTTPS и решения по FCM-проекту.

## F-19. Данные пользователя: экспорт и удаление

Экспорт всех данных пользователя по запросу и полное удаление с анонимизацией (NFR 5.2). Аудит обеих операций. Небольшая фича, закрывает требования к персональным данным.

## Документация фич

Каждая фича документируется в отдельной папке `docs/features/<номер>-<краткое-название>/` (например, `docs/features/F-3-settings/`). Внутри папки — 4 обязательных документа: бизнес-описание фичи (`business-description.md`), системное описание фичи (`system-description.md`), план работ для бэкенда (`backend-plan.md`) и план работ для фронтенда (`frontend-plan.md`). Подробные правила — в `AGENTS.md`, раздел «Структура документации фич».

## Следующие шаги

1. Для каждой фичи перед разработкой создаётся папка в `docs/features/` с 4 документами (см. раздел выше и `AGENTS.md`): бизнес-описание, системное описание и два плана работ — для бэкенда и фронтенда, по образцу авторизации (`docs/technical/auth/`).
2. Первая пара для параллельной работы — F-1 (инфраструктура) и подготовка документации F-3–F-6; F-2 стартует сразу после F-1 по готовым планам.
3. Открытые решения, которые нужно принять заранее: платёжный провайдер (F-15), перечень ИИ-сценариев и промты (F-14, F-16), перечень достижений (F-17).
4. Зависимости можно читать из реестра выше: фича готова к планированию, когда все её зависимости отмечены выполненными в этом документе.
