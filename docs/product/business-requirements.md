# Бизнес-требования к таск-трекеру

## 1. Цель продукта

Таск-трекер помогает пользователю организовывать личные дела по жизненным направлениям, планировать работы, управлять задачами на канбан-доске и быстро сохранять мысли до их последующей обработки.

Основная ценность продукта — единое понятное место для планов, текущих задач и неразобранных идей.

## 2. Пользователь

Первая версия рассчитана на одного пользователя, который ведёт собственные дела. Совместная работа, роли и доступы не входят в текущий объём.

## 3. Основные сущности

| Сущность | Назначение | Обязательные данные |
| --- | --- | --- |
| Ветка | Направление жизни или деятельности: работа, спорт, здоровье, дом и т. п. | Название |
| План работ | Набор связанных задач внутри одной ветки | Название, ветка |
| Задача | Конкретное действие в ветке, при необходимости — в плане работ | Заголовок, приоритет, ветка |
| Входящая мысль | Идея или дело, которое ещё не оформлено как задача и не связано с веткой или планом | Текст |
| Архив | Скрытое от обычного просмотра хранилище удалённых сущностей | Тип сущности, дата архивирования |
| История изменений | Журнал изменений сущностей | Сущность, дата и содержание изменения |
| Персональные настройки | Индивидуальные настройки пользователя | Единица оценки, при необходимости длительность помидора |
| Заметка | Свободная запись знаний или информации в выбранной области | Заголовок, содержание, область |
| Папка заметок | Иерархическая папка для группировки заметок | Название |
| Запись дневника | Личная датированная запись пользователя | Дата, текст |
| Медиафайл дневника | Фото или видео, прикреплённое к записи дневника | Файл, запись дневника |
| Игровой профиль | Игровой прогресс пользователя | Уровень, опыт, настройки |
| Навык | Направление развития игрового персонажа | Название, уровень навыка |
| Достижение | Игровая награда за выполненное условие | Название, условие |
| Игровая валюта | Валюта для покупки виртуальных предметов | Баланс |
| Личный бюджет | Условный денежный баланс, заработанный за выполненные задачи | Баланс |
| Подписка | Уровень доступа пользователя к платным функциям | Тариф, статус, период действия |
| Привычка | Повторяемое ежедневное действие с целевым значением | Название, тип, дневная цель |
| Дневной прогресс привычки | Результат выполнения привычки за конкретный день | Привычка, операционный день, фактическое значение |

Одна ветка может содержать несколько планов работ. Один план работ содержит от одной до неограниченного числа задач. Задача относится к одной ветке и может быть дополнительно привязана к одному плану работ.

## 4. Функциональные требования

### 4.1. Ветки

Пользователь должен иметь возможность:

- просматривать список веток;
- создавать, редактировать и архивировать ветки;
- открывать ветку и видеть её планы работ и связанные задачи.

Примеры веток: «Работа», «Спорт», «Здоровье», «Дом».

### 4.2. Планы работ

Пользователь должен иметь возможность:

- создавать план работ внутри выбранной ветки;
- просматривать планы работ ветки;
- изменять название плана;
- архивировать план работ;
- видеть задачи, входящие в план.

### 4.3. Задачи

Для каждой задачи должны поддерживаться поля:

| Поле | Обязательность | Описание |
| --- | --- | --- |
| Заголовок | Да | Краткая формулировка задачи |
| Описание | Нет | Детали, контекст или ожидаемый результат |
| Дата выполнения | Нет | День, на который запланировано выполнение |
| Приоритет | Да | Категория по матрице Эйзенхауэра |
| Статус | Да | Текущее состояние на канбан-доске |
| Ветка | Да | Направление, к которому относится задача |
| План работ | Нет | План внутри ветки, к которому относится задача |
| Оценка | Да | Плановая трудоёмкость в часах или помидорах |
| Фактическое время | Да при завершении | Фактически затраченное время; указывается при переводе задачи в «Готово» |
| Сложность | Да | Лёгкая, средняя или сложная; влияет на опыт и игровую валюту |
| Триггер ожидания | Для статуса «Ожидает» — да | Событие или действие, которого ожидают для продолжения задачи |
| Дата возврата к задаче | Нет | Дата, когда следует вернуться к ожидающей задаче |

Пользователь должен иметь возможность создавать, просматривать, редактировать и архивировать задачи, а также менять их статус и дату выполнения.

Для статуса задачи используются колонки: «К выполнению», «В работе», «Ожидает», «Готово».

Для приоритета задачи используется матрица Эйзенхауэра:

| Приоритет | Значение |
| --- | --- |
| Срочно и важно | Требует приоритетного выполнения |
| Не срочно, но важно | Требует планирования |
| Срочно, но не важно | Требует быстрого внимания |
| Не срочно и не важно | Не требует срочного внимания |

При создании или редактировании задачи пользователь должен иметь быстрые варианты планирования: «Сделать сегодня» и «Сделать завтра». Эти действия устанавливают соответствующую дату выполнения.

При создании задачи пользователь должен указать её плановую оценку и сложность в единице, выбранной в персональных настройках. Для сложности доступны значения: «Лёгкая», «Средняя», «Сложная». При переводе задачи в статус «Готово» пользователь обязан указать фактически затраченное время в той же единице. Без фактического времени завершить задачу нельзя.

При переводе задачи в статус «Ожидает» пользователь должен указать триггер ожидания — событие или действие, после которого работу можно продолжить. Дополнительно можно указать дату возврата к задаче.

### 4.4. Общая канбан-доска

В приложении должна быть единая канбан-доска, объединяющая задачи из всех веток и планов работ.

Доска должна поддерживать два режима отображения:

- **Сегодня** — отображаются задачи, у которых дата выполнения совпадает с текущей датой;
- **Общий** — отображаются активные задачи независимо от даты выполнения.

Пользователь должен иметь возможность переключаться между режимами. На карточке задачи должны быть видны как минимум заголовок, приоритет, ветка и план работ, чтобы было понятно её происхождение.

Перенос задачи между колонками доски должен менять её статус. Изменение даты на «сегодня» должно включать задачу в режим «Сегодня».

В режиме «Сегодня» завершённые задачи отображаются в колонке «Готово». В общем режиме завершённые задачи по умолчанию не отображаются. Пользователь может открыть завершённые задачи за последний месяц; более ранние завершённые задачи должны быть доступны отдельным действием.

### 4.5. Входящие мысли и дела

В приложении должен быть отдельный раздел «Входящие» для быстрых записей мыслей, идей и дел, которые ещё не стали задачами.

Входящая мысль не привязана к ветке, плану работ или задаче. Пользователь должен иметь возможность:

- создать, изменить и архивировать запись;
- просмотреть список неразобранных записей;
- преобразовать запись в задачу, выбрав ветку, план работ, приоритет и при необходимости дату выполнения;
- архивировать исходную запись после преобразования в задачу.

### 4.6. Персональные настройки оценки

По умолчанию единицей оценки и отображения времени являются часы. Пользователь может в персональных настройках выбрать помидоры как единицу оценки и указать длительность одного помидора в минутах.

Плановая оценка и фактическое время хранятся в системе в часах. При выбранной единице «помидоры» приложение пересчитывает значения для отображения пользователю и по умолчанию округляет их до целого числа.

### 4.7. Заметки

В приложении должна быть система заметок для хранения информации в разных областях. Организация заметок должна работать через иерархические папки, как в файловой системе компьютера. Пользователь должен иметь возможность:

- создавать, переименовывать, перемещать, просматривать и архивировать папки;
- создавать вложенные папки на неограниченную глубину;
- создавать, редактировать, просматривать, искать и архивировать заметки;
- размещать и перемещать заметки в папках;
- быстро переходить между папками и заметками внутри них.

Заметки не являются задачами, не отображаются на канбан-доске и не требуют привязки к ветке, плану работ или входящим.

### 4.8. Личный дневник

В приложении должен быть отдельный раздел личного дневника. Пользователь должен иметь возможность:

- создавать, редактировать, просматривать и архивировать записи дневника;
- указывать дату записи;
- прикреплять к записи фото и видео по желанию;
- просматривать историю записей в хронологическом порядке;
- удобно переходить к записям за нужную дату или период.

Поддерживаются распространённые мобильные форматы фото: JPEG/JPG, PNG, HEIC и WebP; видео: MP4 и MOV. Максимальный размер загружаемого фото — 10 МБ, видео — 100 МБ. Если файл превышает лимит, приложение должно попытаться автоматически сжать его; если после сжатия лимит всё ещё превышен, пользователь получает понятное сообщение и не может прикрепить этот файл.

### 4.9. Игровой режим

Игровой режим — опциональная функция. Пользователь включает или выключает его в персональных настройках. При выключенном режиме игровые элементы, прогресс и валюты не отображаются в основном интерфейсе, а накопленные данные сохраняются.

При включённом игровом режиме пользователь должен иметь отдельное окно игрового профиля, в котором видны:

- персонаж;
- текущий уровень и шкала опыта;
- навыки;
- инвентарь и экипированные вещи;
- достижения;
- баланс игровой валюты и личного бюджета.

За завершение задачи пользователь получает опыт, рассчитываемый по фактическому времени и сложности задачи. Для гибкой настройки используется формула `опыт = x × k × e`, где `x` — фактическое время в часах, `k` — коэффициент сложности, а `e` — базовое количество опыта за час лёгкой задачи из настроек игрового режима. По умолчанию `e` равно 5. Коэффициенты сложности: лёгкая — 1, средняя — 1,5, сложная — 2.

Максимальный уровень — 10 000. Для перехода на каждый следующий уровень требуется в 1,5 раза больше опыта, чем для предыдущего.

Игровой профиль содержит базовые навыки, отражающие ключевые зоны развития: сила, ловкость, интеллект, выносливость и харизма.

Для каждой задачи приложение должно автоматически определять один или несколько навыков, на которые влияет её выполнение. Для этого приложение передаёт в DeepSeek сведения о задаче — заголовок, описание, ветку, план работ, приоритет и сложность. DeepSeek возвращает навыки и долю опыта для каждого из них; сумма долей должна составлять 100 %. При завершении задачи полученный опыт распределяется между указанными навыками согласно этим долям.

Запросы к DeepSeek должны обрабатываться через отдельную очередь. Завершение задачи не зависит от доступности DeepSeek: при временной ошибке задача остаётся завершённой, а распределение опыта по навыкам выполняется повторно из очереди. Пользователь не изменяет предложенное распределение вручную в первой версии. В игровом профиле пользователь должен видеть текущий опыт каждого навыка и количество опыта, полученное за каждую завершённую задачу.

Игровой режим должен поддерживать достижения. Перечень достижений и условия их получения будут определены позднее.

За завершение задач пользователь получает два типа условной валюты:

- **игровая валюта** — используется для приобретения скинов, предметов инвентаря и других виртуальных вещей. Она рассчитывается по формуле `игровая валюта = x × k × z`, где `x` — фактическое время в часах, `k` — коэффициент сложности, а `z` — заданная пользователем в настройках базовая награда за час лёгкой задачи; значение `z` по умолчанию равно 5;
- **личный бюджет** — рассчитывается по той же формуле, что и игровая валюта: `личный бюджет = x × k × z`, где `x` — фактическое время в часах, `k` — коэффициент сложности, а `z` — заданная пользователем стоимость часа лёгкой задачи для личного бюджета. Пользователь может вручную списывать личный бюджет на свои желания, например покупку игры или поход в кино.

### 4.10. Подписки и уровни доступа

В приложении должна быть система уровней доступа, определяющая доступность платных функций.

| Тариф | Доступ |
| --- | --- |
| Старт | Бесплатный доступ к базовым функциям приложения: веткам, планам, задачам, канбан-доске, входящим, заметкам, дневнику и трекеру привычек |
| Прогресс | Доступ к игровому режиму, игровому профилю, опыту, навыкам, достижениям и двум условным валютам |
| Эволюция | Всё из «Прогресса», а также ИИ-анализ и будущие функции персонального ИИ-помощника |

Игровой режим в тарифе «Старт» доступен как пробная функция в течение 14 дней с момента создания пользователем первой задачи. После окончания пробного периода игровой режим и его интерфейс блокируются до приобретения тарифа «Прогресс» или «Эволюция»; игровые данные и накопленный прогресс сохраняются.

Для тарифов «Прогресс» и «Эволюция» должны поддерживаться несколько вариантов периода оплаты, включая помесячную и годовую подписку. Пользователь может перейти с «Прогресса» на «Эволюцию» с доплатой за неиспользованную часть текущего периода. После окончания подписки игровые данные сохраняются и становятся доступны сразу после повторной покупки подходящего тарифа.

Тариф «Эволюция» предоставляет доступ к ИИ-анализу. В следующих версиях в него войдут анализ недели и задач, а также персональный ИИ-помощник, которому пользователь сможет поручать исследовательские и организационные задачи, например: «Проанализируй рынок и найди пять лучших интернет-магазинов». Конкретный перечень ИИ-сценариев, источники данных, ограничения и результат работы помощника будут определены отдельно.

### 4.11. Ежедневный трекер привычек

На главной странице должен отображаться трекер привычек на текущий операционный день. Операционный день начинается и завершается в 04:00 по московскому времени (МСК): в 04:00 незавершённый дневной прогресс закрывается, сохраняется в истории, а для всех привычек начинается новый чистый дневной прогресс.

Пользователь должен иметь возможность создавать, редактировать, приостанавливать, архивировать и просматривать привычки. Для каждой привычки указываются название, тип учёта и дневная цель. Поддерживаются два типа:

- **Отметки** — пользователь задаёт число повторений в день. Интерфейс показывает соответствующее число пустых ячеек; пользователь отмечает их по мере выполнения. Например, для привычки «Выпить стакан воды» с целью 6 отображаются шесть ячеек.
- **Количество** — пользователь задаёт числовую дневную цель и единицу измерения. В течение дня он вводит или изменяет фактическое накопленное значение. Например, для привычки «Отжимания» можно указать цель 50 повторений и изменять фактическое число по мере выполнения.

Дневной прогресс привычки сохраняется в истории и не удаляется при ежедневном обнулении. Пользователь должен иметь возможность просматривать историю выполнения привычек.

Пользователь может изменить дневную цель привычки в течение операционного дня. При изменении цели накопленный прогресс сохраняется, а ИИ-награда за день рассчитывается относительно новой дневной цели.

Если игровой режим активен и доступен по текущему тарифу, в 04:00 приложение должно передать результаты привычек за завершившийся операционный день в ИИ-очередь. ИИ-анализ определяет начисления опыта, игровой валюты и опыта навыков по итогам выполнения привычек. Для оценки используется подготовленный промт с примерами и данными привычки: название, тип, дневная цель, фактический прогресс и контекст других пользовательских данных. ИИ должен дать сопоставимую оценку награды относительно этих примеров и данных. Сложность привычки и связанные навыки определяет только ИИ; пользователь не изменяет их вручную в первой версии. Обработка выполняется асинхронно и не должна блокировать создание нового операционного дня; результаты начислений становятся видны пользователю после завершения обработки очереди.

## 5. Базовые правила

- Дата выполнения — необязательное поле: задача без даты отображается в общем режиме доски, но не в режиме «Сегодня».
- Выбор «Сделать сегодня» или «Сделать завтра» заменяет ранее указанную дату выполнения.
- Задача остаётся связанной со своим планом и веткой при смене даты или статуса.
- «Входящие» предназначены для неразобранных записей и не отображаются на канбан-доске, пока не преобразованы в задачи.
- Физическое удаление веток, планов, задач и записей из «Входящих» не допускается: действие удаления переводит сущность в архив и исключает её из обычных списков и досок.
- При архивировании ветки архивируются все входящие в неё планы и задачи. При архивировании плана архивируются все входящие в него задачи.
- Пользователь должен иметь возможность восстановить из архива отдельную сущность. При восстановлении ветки пользователь может восстановить её вместе со всем архивным содержимым. При восстановлении задачи автоматически восстанавливаются только необходимые родительские ветка и план работ; остальные архивированные сущности в этих родителях не восстанавливаются.
- Все изменения веток, планов работ, задач и входящих записей должны сохраняться в истории, включая создание, редактирование, изменение статуса, изменение даты и архивирование. История хранится технически и не отображается пользователю в первой версии.
- Ежедневный прогресс привычек и начисления за привычки должны сохраняться в истории.

- уведомления и напоминания;
- повторяющиеся задачи;
- вложенные подзадачи;
- интеграции с внешними календарями и сервисами;
