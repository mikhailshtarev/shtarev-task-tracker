# Инструкции для агентов

- Перед началом прочитай `README.md` и `package.json`.
- Не изменяй файлы вне области текущей задачи.
- Сохраняй существующий стиль кода и структуру каталогов.
- Делай минимальный набор изменений, необходимый для задачи.
- Не проводи несвязанный рефакторинг без явного запроса.
- Никогда не добавляй ключи, токены, пароли или `.env` в Git.
- При изменении API обновляй типы, валидацию и документацию endpoint'ов.
- Не меняй публичные контракты API без обратной совместимости или миграции.
- Любое изменение схемы БД оформляй миграцией.
- Не редактируй уже применённые миграции.
- Компоненты должны быть небольшими и иметь одну ответственность.
- Ошибки пользователя должны быть понятными, без технических деталей.
- Валидируй все внешние входные данные на сервере.
- Не добавляй новые зависимости для небольшой задачи без необходимости.
- Избегай N+1 запросов к базе данных.
- Не оптимизируй преждевременно; сначала измерь проблему.
- Не доверяй данным из URL, формы, cookie и внешних API.
- Не храни производные данные в state без необходимости.
- Не выполняй `git reset --hard`, `git push --force` и не удаляй ветки `develop`, `main`, `release/**`.
- Перед добавлением библиотеки проверь, нельзя ли решить задачу уже имеющимися средствами.
- Если требование неоднозначно и выбор заметно влияет на архитектуру, сначала задай вопрос.
- В остальных случаях выбери наиболее консервативное решение и явно укажи допущение.
- При добавлении зависимости объясни, зачем она нужна.

## Итог работы

В конце кратко укажи:

1. Что изменено.
2. Какие проверки выполнены.
3. Что осталось сделать или какие есть риски.
